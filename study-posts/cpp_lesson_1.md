# C++进阶笔记：第1课——值语义与对象模型

> 暑假试图梳理一些C++机制的系列笔记，计划大概22课。

---

## 1.1 一个根本问题：C++里的"对象"到底是什么？

在C++里，**对象就是对象**，不是"指向对象的指针"，不是"对象的引用"。

```cpp
int main() {
    std::string s = "hello";  // s 就是一个对象，不是指针，不是引用
    // s 本身就拥有那块内存，那块内存和 s 的生命周期绑在一起
}
```

这句话听起来像废话，但确实是C++最核心的设计哲学：**值语义（Value Semantics）**。

> **值语义的意思是：对象自己拥有并管理自己的资源。**

当你写下：
```cpp
std::string a = "hello";
std::string b = a;  // b 拥有属于自己的一份 "hello"
```

`b` 不是指向 `a` 的别名，`b` 是一个**全新的、独立的对象**，它内部有一份自己的内存拷贝。修改 `b` 不会影响 `a`。

这和Java、Python等语言很不一样。在C++里，**默认就是拷贝，默认就是拥有**。

## 1.2 对象住在哪里？

C++的对象可以住在两个地方，这直接决定了它的生死：

| 存储位置 | 写法 | 生命周期 | 特点 |
|:---|:---|:---|:---|
| **栈（stack）** | `Obj a;` | 离开作用域自动销毁 | 自动、高效、RAII的基础 |
| **堆（heap）** | `Obj* p = new Obj();` | 直到 `delete` 才销毁 | 手动管理，容易忘记释放 |

```cpp
void foo() {
    std::string s = "local";  // s 住在栈上
    // foo 结束时，s 自动销毁，内存自动回收
}

void bar() {
    std::string* p = new std::string("heap");  // 对象住在堆上
    // bar 结束时，p 这个指针变量被销毁了
    // 但堆上的 "heap" 对象还在！没人管它了！
    // 这就是内存泄漏
}
```

**核心认知：**

> C++鼓励对象住在栈上。能用栈对象解决的，就不要用堆。

栈对象的生命周期和作用域绑定，**自动创建、自动销毁**，这是C++资源管理的根基。写算法题的时候如果满屏 `new` 还不 `delete`，其实就已经背离了C++的设计哲学。

---

## 1.3 值语义带来的资源转移链条

既然对象默认是"拥有资源"的，那当一个对象需要把自己的资源给另一个对象时，C++设计了三条路径：

```
对象A  =====>  对象B

路径1：拷贝（Copy）—— "我复制一份给你，你也有，我也有"
路径2：移动（Move）—— "我把我的给你，我变成空的，你拥有"
路径3：引用（Reference）—— "我不给，你借我的用，但别修改"
```

这三条路径，对应着C++最核心的三个机制：
- **拷贝构造 / 拷贝赋值**（第6、7课）
- **移动构造 / 移动赋值**（第8、9课）
- **引用与const**（第2、3课）

理解了这个链条，后面所有语法都会变得清晰——它们不是孤立的语法点，而是围绕"资源怎么转移"这个问题的不同解决方案。

## 1.4 小例子：感受值语义

```cpp
#include <iostream>
#include <string>

void print(const std::string& s) {
    std::cout << s << std::endl;
}

int main() {
    std::string a = "hello";  // a 是一个对象，拥有 "hello"
    std::string b = a;        // b 拷贝了 a，现在有两个独立的 "hello"

    b += " world";            // 修改 b，a 完全不受影响

    std::cout << "a: " << a << std::endl;  // a: hello
    std::cout << "b: " << b << std::endl;  // b: hello world

    print(a);  // 传引用，不拷贝，只借来读一下
}
```

---

## 本课重点

1. **C++默认是值语义**：对象拥有资源，拷贝是默认行为
2. **优先用栈对象**：`Obj a;` 比 `new Obj()` 更C++
3. **三条资源转移路径**：拷贝、移动、引用——这是贯穿整个系列的主线

---

## 思考题

为什么C++要设计"值语义"作为默认？如果默认是指针语义（像Java那样），会带来什么问题？

结合自己写算法题的经验想想：如果每次赋值都是传引用而不是拷贝，那些隐式的副作用会有多难debug？值语义让对象的行为更像"值"本身——一个int赋值给另一个int，你从来不会担心原int被改掉。C++把这个直觉推广到了所有对象上。当然，代价是拷贝可能很贵，所以后面才会引入移动语义和引用——但那是优化手段，值语义才是默认假设。
