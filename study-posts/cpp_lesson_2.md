# C++进阶笔记：第2课——引用与别名机制

> 继续梳理C++核心机制。上一课讲了值语义和对象模型，今天解决一个很多初学者会困惑的问题：C++为什么既有指针，又有引用？

---

## 2.1 引用的本质：一个必须从一而终的别名

引用（reference）就是**对象的别名**。它必须在诞生时就绑定到一个对象，而且**一辈子不能改绑**。

```cpp
int a = 10;
int& ref = a;  // ref 是 a 的别名，从此 ref 就是 a，a 就是 ref

ref = 20;      // 等价于 a = 20
std::cout << a; // 输出 20
```

关键点：
- `int& ref = a;` 这里 `&` 不是取地址，是**声明这是一个引用**
- 引用**必须初始化**，不能先声明后绑定
- 引用**不占额外内存**（语义上），它只是给已有对象起了个新名字

---

## 2.2 引用 vs 指针：不是替代，是不同层面的工具

| | 指针 | 引用 |
|:---|:---|:---|
| 能否为空？ | 可以 `nullptr` | **不可以**，必须绑定有效对象 |
| 能否重新指向？ | 可以改指别的对象 | **不可以**，一旦绑定终身不变 |
| 语法 | 需要解引用 `*p` | 直接使用，像原对象一样 |
| 本质 | 存储地址的变量 | 对象的别名 |

```cpp
int a = 10, b = 20;

// 指针：灵活，但也危险
int* p = &a;
p = &b;      // 没问题，p现在指向b
*p = 30;     // b变成30

// 引用：忠诚，但受限
int& ref = a;
// ref = b;   // 这不是"让ref绑定b"，这是"把b的值赋给a"！
```

**核心区别**：`ref = b` 对于引用来说，永远等价于 `a = b`。因为引用不是独立的变量，它没有自己的"存储空间"来放一个新地址。

---

## 2.3 为什么C++需要引用？

既然指针已经能完成"间接访问"的工作，为什么还要发明引用？

**答案：为了语法优雅和运算符重载。**

想象一下，如果没有引用，你想写一个交换函数：

```cpp
// 用指针的版本：调用时必须传地址，麻烦
void swap(int* a, int* b) {
    int tmp = *a;
    *a = *b;
    *b = tmp;
}
swap(&x, &y);  // 调用时还要写&，容易忘

// 用引用的版本：调用时就像普通传值，但实际修改了原对象
void swap(int& a, int& b) {
    int tmp = a;  // 不需要解引用，直接像用变量一样
    a = b;
    b = tmp;
}
swap(x, y);  // 干净！直观！
```

引用让"按引用传参"的语法和"按值传参"一样自然，这是C++追求**零开销抽象**的体现：功能强大，但用起来不繁琐。

---

## 2.4 const 引用：只读借用

如果你不想修改原对象，只是借来看看：

```cpp
void print(const std::string& s) {
    // s += "!";  // 编译错误！承诺了不修改
    std::cout << s << std::endl;
}

std::string msg = "hello";
print(msg);  // 不拷贝，不修改，只读
```

`const std::string&` 是C++中最常见的函数参数类型：**避免拷贝开销，同时保证不修改原对象**。

---

## 2.5 引用的限制：不能引用临时对象？

等等，那这条代码合法吗？

```cpp
const std::string& ref = "hello";  // 合法！
std::string& ref2 = "hello";       // 非法！编译错误！
```

为什么加了 `const` 就能绑定字符串字面量（临时对象），不加就不行？

这涉及到C++的**值类别**（左值、右值）——第3课会专门讲。现在只需要记住：**const 引用可以延长临时对象的生命周期**，这是一个很实用的技巧。

---

## 本课重点

1. **引用是别名**，必须初始化，终身不能改绑
2. **引用不是指针的替代**，而是让语法更优雅的工具
3. **`const T&`** 是C++最常用的函数参数形式：零拷贝、只读、安全
4. 引用让运算符重载和函数接口变得干净（后面会大量用到）

## 课后练习与答案

### 练习题

下面这段代码输出什么？为什么？

```cpp
#include <iostream>

void foo(int& x) {
    x = 100;
}

void bar(int* x) {
    *x = 200;
}

int main() {
    int a = 1;
    int& ref = a;
    int* ptr = &a;

    foo(ref);      // 调用1
    std::cout << a << std::endl;

    bar(ptr);      // 调用2
    std::cout << a << std::endl;

    // 下面这行能编译吗？
    // foo(ptr);    // 调用3
    // bar(ref);    // 调用4
}
```

### 答案

**调用1** `foo(ref)`：`ref` 的类型是 `int&`，传给 `int& x` 完全匹配。`foo` 内部 `x = 100` 等价于 `a = 100`。输出 `100`。

**调用2** `bar(ptr)`：`ptr` 的类型是 `int*`，传给 `int* x` 完全匹配。`bar` 内部 `*x = 200` 解引用后修改 `a`。输出 `200`。

**调用3** `foo(ptr)`：**编译错误**。`ptr` 的类型是 `int*`，而 `foo` 的参数类型是 `int&`，两者是完全不同的类型，不能隐式转换。指针和引用之间不存在自动转换关系。

**调用4** `bar(ref)`：**编译错误**。`ref` 的类型是 `int&`，而 `bar` 的参数类型是 `int*`，同样不能隐式转换。要传引用给指针参数，必须显式取地址：`bar(&ref)`。

**核心 takeaway**：`int&` 和 `int*` 是两种完全不同的类型，虽然底层都涉及间接访问，但语法层面互不兼容。引用传参时"看起来像传值"，但类型系统仍然严格区分。
